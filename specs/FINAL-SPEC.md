# 长离桌宠最终项目规格（Codex 执行版）

> 目标：制作一个 Windows 平台的 Q 版“长离”互动桌宠。  
> 视觉与交互体验参考 B 站 UP 主“宇痕冫”的桌宠系列，以及 Bongocat 类键鼠联动桌宠。
>
> 本文件作为 Codex 的主要项目规格。除非用户后续明确修改需求，否则以本文件为准。

# 2. 项目核心目标

本项目不是：

> “做一张会动的长离图片。”

而是：

> **制作一个拥有宇痕系 Bongocat 交互逻辑的长离 Q 版桌宠。**

核心体验：

- 用户打字 → 长离同步敲键盘
- 用户移动 / 点击鼠标 → 长离同步操作鼠标
- 用户使用手柄 → 长离产生对应动作
- 用户可通过快捷键切换表情和完整动画
- 桌宠可长期驻留桌面
- 低资源占用
- 不记录用户输入内容
- 默认离线

优先级：

**桌宠交互感 > Q 版萌感 > 长离辨识度 > 特效丰富度**

# 3. 视觉规格

## 3.1 整体风格

必须明显接近宇痕系 Q 版桌宠，而不是普通二次元插画。

要求：

- 超大头
- 极小身体
- 头部约占人物整体视觉面积 60%～75%
- 身体只露肩膀和少量上半身
- 五官集中
- 圆脸
- 幼态比例
- 圆润小手 / 小肉团手型
- 粗轮廓线
- 平涂为主
- 少量柔和阴影
- 背景透明
- 桌面元素简单

避免：

- 正常人体比例
- 写实手部
- 海报式场景
- 大面积复杂背景
- 大量文字
- 过度华丽凤凰特效
- 过度精细的插画光影

# 4. 长离辨识度要求

需要保留：

- 珊瑚粉 / 红粉色长发
- 发尾偏白
- 金红色瞳孔
- 黑 / 红 / 金中式装饰
- 花 / 蝴蝶形发饰
- 黑色丝带
- 金色挂件
- 流苏
- 凤凰 / 火焰元素

可以为了 Q 版适当简化服装细节。

但必须做到：

> 一眼能认出是长离，而不是普通粉发原创角色。

## 6.5 位置记忆

- Y

## 6.6 多显示器

必须支持：

- 主屏
- 副屏
- 跨屏拖动
- 屏幕变化后自动修正位置

## 6.7 防止完全拖出屏幕

提供：

- 保持部分可见
- 重置位置功能

# 7. 核心功能：键盘联动

这是整个项目最重要的功能之一。

用户输入键盘时：

- 长离同步做敲键盘动作
- 停止输入后回到待机状态
- 连续输入时动作连贯
- 不需要真实模拟十指

建议键盘分区：

左手：

- Q W E R T
- A S D F G
- Z X C V B

右手：

- Y U I O P
- H J K L
- N M
- Enter
- Backspace
- Space

目标：

> 输入发生 → 桌宠立即有对应视觉反馈。

---

# 8. 三种输入模式

## 8.1 键鼠模式

Keyboard + Mouse（键盘 + 鼠标）

默认模式。

表现：

- 键盘 → 敲键盘
- 鼠标移动 → 鼠标手轻微变化
- 左键 → 左键动作
- 右键 → 右键动作
- 滚轮 → 滚轮动作或轻微反馈

## 8.2 纯键盘模式

Keyboard Only（纯键盘）

表现：

- 双手都放在键盘
- 鼠标移动不影响手部
- 所有主要输入反馈集中在敲键盘

适合：

- 写代码
- 写文档
- 聊天
- 纯键盘操作

## 8.3 手柄模式

Gamepad（游戏手柄）

至少支持常见 XInput（微软手柄输入接口）兼容手柄。

响应：

- 左摇杆
- 右摇杆
- A
- B
- X
- Y
- LB
- RB
- LT
- RT
- 十字键

没有手柄时：

- 不报错
- 不影响其他模式

# 14. Idle（待机）系统

- 动作幅度小

# 23. 状态优先级

必须建立 State Machine（状态机）。

不要依赖大量散乱的 if / else。

建议优先级：

1. 手动完整动画
2. 手动表情
3. 手柄输入
4. 鼠标点击
5. 键盘输入
6. Idle
7. Sleep

原则：

完整动画播放期间不要被普通按键立即打断。

# 30. 隐私要求

键盘监听只用于：

> 判断应该播放哪个动作。

绝对不能：

- 保存用户完整输入
- 记录密码
- 保存按键日志

# 40. Astra 的使用方式

尽量给 Astra 一个完整工作包，而不是频繁发送极小修改。

推荐：

> 完成某一整个模块，自行检查当前代码，完成实现后运行构建和测试，遇到问题直接修复。不要提前开始下一阶段。

目的：

- 减少上下文往返
- 节省 Astra 配额
- 让模型完成完整任务闭环

---

# 41. Codex 工作原则

每一轮任务：

1. 先阅读已有代码
2. 不重复造已有功能
3. 确认架构后再修改
4. 尽量一次完成一个完整模块
5. 修改后运行格式化
6. 运行静态检查
7. 运行构建
8. 有测试则运行测试
9. 编译报错直接修复
10. 不把半成品当作完成
